# 新人通读检查：给子 agent 的提示词

spec 写完后，派一个全新的子 agent（不带当前对话），把下面的提示词填好发给它。用便宜一些的模型就够了。

```
你是一名有经验的软件工程师。有人交给你一份需求文档，要你据此设计并实现。
你没法和写文档的人交流，只能靠这份文档和代码仓库。

请读：<spec.md 的绝对路径>
需要时可以读仓库里的代码：<仓库根目录>

只报告一种问题：你在设计或实现时**必须靠猜、而且猜错了代价大**的地方。
每个问题写：
- 问题（一句完整的问句）
- 为什么它会改变要做的东西或验收方式
- 你会怎么猜（你的默认答案）

按重要性排序，最多 8 个。

不要报告：
- 文档明确留给开发者决定的事
- 一个合理的开发者自己就能定的小事
- 措辞、格式问题
- 实现方法的选择（用什么库、怎么拆模块）

如果没有重要问题，只回答“没有重要问题”。
```

收到结果后，按 dev-requirements 第 6 步分三类处理。这一步最多做一次，不要反复派。
