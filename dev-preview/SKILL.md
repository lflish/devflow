# dev-preview：交付录屏

让用户直接看到这次功能怎样操作、实际发生了什么。视频是验收证据的补充，测试是否通过仍以断言、报告和独立验证为准。

## 先选交付方式

读本次需求、已有测试报告和项目的浏览器入口；在 devflow 流程里沿用已选环境，单独调用时只处理用户指定的功能，不新建需求流程、不自动部署。

- 已有录像能对应当前被测代码、场景和实际结果：直接核验并复用。仅文稿更新、已有证据确认产品代码未变时，不为新提交号重录。
- 有界面改动：选一条能看懂变化的短流程，通常几十秒即可；涉及校验时展示拒绝与成功，涉及保存时展示刷新回读。只选与本次需求相关的步骤，不重演全部测试。
- 纯 API、后台或库改动：交付请求/响应、命令结果或报告，不造一个界面来录。用户另有演示要求时按其范围做。
- 当前浏览器没有可用的原生录像能力：优先使用项目已支持的录制入口；仍不可用就交付关键截图和操作步骤，标明“截图替代，未录屏”，不把截图拼接称为真实录屏。

## 录制与核验

新录制时读 [references/recording.md](references/recording.md)，复用项目 Playwright 测试、登录方式和专用测试浏览器；浏览器选择遵循 [dev-test/browser.md](../dev-test/references/browser.md)。不要为一段录像另建测试框架，也不要接管用户个人浏览器。

1. **确认对象**：核对被测服务的实际运行版本，记录应用环境、访问地址、浏览器所在机器与视频保存位置。浏览器在本机访问远端应用时，要明确“本机录制、远端服务”；健康检查成功不能证明版本。版本不明的录像只能标为演示，不能作为本次交付已验证的证据。
2. **沿用授权**：按项目环境和数据规则操作。需要写入测试数据时先核对已有授权，已有同范围授权不重复问；缺少必要授权只暂停对应操作。录制不额外授权生产变更、真实付费调用或公开上传。非登录功能默认在录制前完成登录；验收登录流程本身时，使用获准的测试账号并遮蔽敏感输入和结果。含密码、Key、Token 或个人数据的响应和日志先脱敏，认证状态与未脱敏的秘密不进入成片和报告。
3. **真实执行**：按原场景操作，等待真实的页面/接口结果并做原有断言；必要时刷新回读。记录使用了哪些模拟响应、测试上游或真实外部服务，只声明实际覆盖到的行为。失败如实保留在结果里，不用字幕或剪辑把失败改成成功。
4. **收尾**：等待录像完整落盘；按已授权范围清理本次测试资源，保留原有数据。录制前后核对运行版本，发生漂移时说明影响，不把混合版本录像当作同一版本的结果。
5. **检查成片**：实际播放并跳转到关键步骤，确认文字可读、结果可见、没有秘密。可以裁去空白、加字幕或点击提示，并简要说明处理方式；不重排关键执行顺序或隐去失败。原始录像和测试输出保留在本机证据位置。

## 交付

交付一段视频和几行说明即可，不另造复杂报告。说明至少包括：

- **演示内容与结果**：操作顺序、关键断言、对应验收场景。
- **来源**：录制日期、应用环境与实际版本、浏览器/录制所在机器、原始录像和成片位置。
- **范围**：真实服务或测试替身、覆盖和未覆盖的行为、剪辑/字幕等后期处理。
- **入口**：可播放预览链接或本地文件；可供用户继续体验的测试入口（已有且适合交付时）。

项目仓库里的报告只写环境名和代码版本；真实机器地址按项目约定留在本机配置或本地交付记录，不把凭据、访问码、原始录像和大视频提交到 Git。没有既定产物目录时用本机的 `.devflow-tmp/`，确认它已被 Git 忽略。

需要可分享链接且预览服务可用时，读已安装的 `dview-upload` skill，按 [preview.md](../dev-workflow/references/preview.md) 的配置上传视频并打开链接验证播放/跳转。沿用用户已确定的访问保护偏好；没有该偏好时保留默认保护，访问码和有效期单独交付，不写进页面。没有上传工具、配置为关闭或上传失败时，交付本地文件及原因，不扩大为服务安装或公网暴露任务。

在 dev-test 中，将视频入口和上述说明写入 `test-report.md` 的“交付预览”，并放到现有汇总页；单独调用时直接回复，不强制生成报告或修改验收结论。录屏缺失和测试失败分开记录：普通截图兜底不改变已有验收结果；用户明确要求的录像尚未完成时，要如实说明这项交付未完成。
