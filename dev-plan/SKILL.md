# dev-plan：计划

目标：**计划写到实现时不需要再做决定。** 写清楚已经定下的东西：哪些文件、什么接口、spec 里的具体数值、每个任务用什么测试证明完成。实现者自己能写好的代码细节，不用写。

## 开始

1. 先读 `../dev-workflow/SKILL.md` 的“每次开始时”并照做（包括读 `../dev-workflow/references/decisions.md`）。本阶段还要读同目录下的 `gates.md`、`preview.md`。
2. 状态行“阶段”改为 `dev-plan`。
3. **独立模式**：没有需求文件夹、用户只是要把某件事拆成任务时，按下面的方法拆，把清单直接给用户，不发关口简报、不交接。

**接着做**：已有 tasks.md 时，从没写完的部分继续；已经写完、只差简报的，直接到第 5 步。

## 1. 读

spec.md、design.md（规模“小”时没有）、decisions.md、相关代码。

规模“小”时，在 tasks.md 开头先写“技术方案”：5–10 行，说明改哪里、怎么改、为什么。

## 2. 测试计划

先把每个验收场景分配到测试层级，这张表会直接交给 dev-test 用：

| 场景 | 层级 | 测试名 | 要点 | 谁写 |
|------|------|--------|------|------|
| R1.1 | 单元 | `comments_create_valid_text` | 返回 201，内容原样保存 | T1 |
| R1.3 | 浏览器 | `R1.3 访问码过期后打开评论页` | 显示“访问码已过期”，不显示评论 | dev-test |

- **单元**：纯逻辑、数据转换、规则判断。由负责的任务编写。
- **集成**：模块协作、数据库读写、接口。由负责的任务编写。
- **浏览器**：用户在页面上能看到、能操作的场景。只要有界面，每个关键场景至少一个浏览器测试。**统一由 dev-test 编写**（它负责连接远程浏览器），“谁写”一栏填 `dev-test`；但实现任务要给关键元素加上 `data-testid`，在任务里写明。

再列出 3–5 个**容易出问题、但 spec 没明说的输入或情况**（重复提交、超长输入、并发修改、网络中断、权限边界……），每个写清合理的预期行为，并把对应测试分给负责的任务或 dev-test。spec 没写到，不代表这些情况可以出错。

## 3. 拆任务

按 [references/tasks-template.md](references/tasks-template.md) 写 tasks.md。规则：

- **大小**：一个任务有自己完整的测试循环，完成后系统仍能运行。准备工作、配置、文档并入用到它的任务，不单独成为任务。
- **顺序**：先做能跑通最小闭环的任务，再做扩展。
- **每个任务写清**：
  - 涉及文件（新建 / 修改，带路径）
  - 接口：用到前面任务的什么（签名），给后面任务提供什么（函数名、参数、返回类型）
  - 对应场景（R 编号）和测试（测试名 + 关键断言，用 spec 里的具体值）
  - 完成定义：运行什么命令，看到什么输出
- **不能写不做决定的句子**：“处理边界情况”“添加适当的校验”“为上面写测试”“TBD”都不行，要写具体是哪些。
- **也不要把代码写完**：计划比要写的代码还长，说明写成了代码，改成签名、测试名和断言。

## 4. 自查

- [ ] 每条需求、每个场景都能找到负责的任务或 dev-test 的测试
- [ ] 测试计划表里每个场景都有层级、测试名、谁写
- [ ] 前后任务的名字、签名、类型一致（第 3 个任务叫 `listComments`，第 7 个任务不能叫 `getComments`）
- [ ] 依赖没有循环；完成定义都能执行
- [ ] 没有“TBD”这类不做决定的句子
- [ ] 计划长度没有超过代码本身

发现问题就地改，不用再派评审。提交 tasks.md 和 decisions.md。

## 5. 关口 B，或关口 AB

**规模“标准”——关口 B**：按 preview.md 生成**方案简报页**（方案对比、结构图、任务列表、测试计划表、所有 `d`/`c` 决定），然后按 gates.md 的“关口 B / C”格式在终端给出简报：一句话、页面链接和访问码、`c` 和 `d`（带默认）、其他（任务数、改动文件数、浏览器测试数、风险、后续清单）。状态行写 `待关口：B`，提交，**这一轮结束，等人回复**。

**规模“小”——关口 AB**：不单独做简报页。按 gates.md 的“关口 A / AB”格式，把需求部分（要做 / 不做、场景、假设 H、问题 Q、效果页链接）和本阶段的技术方案、任务数、`d`/`c` 合成一份简报。状态行写 `待关口：AB`，提交，**这一轮结束，等人回复**。

回复按 gates.md 处理。通过后：状态改为“实现中”，清空待关口，阶段改为 `dev-implement`，写变更记录、提交、更新索引，然后读 `../dev-implement/SKILL.md` 并执行。
