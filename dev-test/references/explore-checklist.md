# 探索式检查清单

脚本只能测写到的场景。探索式检查是像人一样把页面实际用一遍，找没想到的问题。范围：这次改动涉及的页面，以及从这些页面能直接到达的页面。

## 每个页面

1. **看**：截图，看布局有没有错乱、重叠、文字被截断、图片缺失、对齐问题。
2. **点**：每个按钮、链接、控件都点一下，是否做了它说的事。
3. **表单**：正常提交；空着提交；填非法值；超长文字；特殊字符（`<script>`、emoji、引号）；连点两次提交。
4. **导航**：进出这个页面的所有路径；浏览器后退；刷新；直接打开深层链接。
5. **状态**：空数据、加载中、出错、数据很多（溢出、分页）时的样子。
6. **控制台**：操作后有没有新的 JS 报错、失败的网络请求（4xx/5xx）。
7. **手机宽度**：把视口改成 390×844 再看一遍（有 `rules.test` 要求或页面面向手机用户时必做）。
8. **权限**：未登录、无权限、访问码错误或过期时的表现。**不要退出或切换人的账号**；需要另一种身份时，用测试账号新开一个 context。

## 问题严重程度

| 程度 | 含义 | 例子 |
|------|------|------|
| 严重 | 核心流程走不通、丢数据、崩溃 | 提交表单报错页；删除没有确认就丢了数据 |
| 高 | 主要功能坏了，没有绕过办法 | 搜索结果错误；上传静默失败；登录跳转死循环 |
| 中 | 能用但有明显问题，有绕过办法 | 页面加载超过 5 秒；只有手机上布局错乱 |
| 低 | 外观细节 | 错别字；1px 对不齐；悬停样式不一致 |

## 问题分类

外观 / 功能 / 体验（没有加载提示、报错只写“出错了”、走进死胡同）/ 内容（错字、占位文字没删）/ 性能（超过 3 秒、页面跳动）/ 控制台报错 / 可访问性（图片没有 alt、表单没有标签、键盘无法操作）。

## 每个问题记录

```markdown
### X3 [高] 连点两次“发表”出现两条一样的评论
- 页面：/v/abc123
- 复现：输入“测试” → 快速点两次“发表”
- 预期：只出现一条
- 实际：出现两条，刷新后仍是两条
- 截图：evidence/X3.png
- 处理：已修复（提交 d4e5f6，回归测试 comments_double_submit_once）/ 未修复：原因
```

严重和高的问题必须修复，或者写清楚为什么修不了；中和低的能顺手修就修，不能就记进报告。
